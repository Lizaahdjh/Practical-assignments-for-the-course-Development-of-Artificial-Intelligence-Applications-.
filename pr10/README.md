# ПР10. Надійний AI-сервіс і AI UX

Помічник оператора підтримки «Сузірʼя»: за встановленими фактами
(номер заявки, строки, куди привезти) модель складає **чернетку
відповіді клієнтові**. Оператор її редагує й надсилає.

Головне в роботі — не сам виклик моделі, а все, що **між HTTP-ендпоінтом
і провайдером**: абстракція провайдера, три таймаути, обмежені повтори,
контрольовані помилки, обмеження частоти й одночасності, фонова
генерація з потоком фрагментів, скасування й підставний провайдер, з
яким усе це можна перевірити без ключа.

## Мета

- Абстрагувати провайдера: решта застосунку не імпортує `openai`.
- Перемикати провайдера (справжній / підставний) і модель **через
  `.env`**, без змін у коді.
- Задати три таймаути (спроба, бездіяльність, весь запит) на основі
  вимірювань.
- Повторювати лише тимчасові збої з backoff+jitter; `Retry-After`
  провайдера враховувати.
- Обмежити одночасність на весь застосунок і частоту — на клієнта.
- Генерувати чернетку у фоні з потоком подій (SSE); стан переживає
  перезавантаження сторінки.
- Скасовувати роботу між фрагментами й спробами.
- Показувати оператору, що відбувається: статус, спроба, провайдер,
  час до першого фрагмента.

## Що змінилося порівняно з ПР9

| Було в ПР9 | Стало в ПР10 |
|---|---|
| Модель генерує відповідь клієнтові | Модель складає чернетку для оператора |
| Синхронний виклик | Фонова генерація + SSE |
| Один провайдер, `openai` у коді | Абстракція `Provider` + два провайдери |
| Повтор лише в шлюзі | Три таймаути + backoff + fallback |
| Немає обмежень частоти | Обмеження на клієнта (429 + Retry-After) |
| Немає скасування | Скасування через `threading.Event` |
| Немає mock | Підставний провайдер із збоями на вимогу |

## Контракт провайдера

`app/providers/base.py`. Решта застосунку знає лише це:

| Клас | Що містить |
|---|---|
| `Request` | `messages`, `max_tokens`, `temperature`, `model`, `metadata` |
| `Chunk` | `text`, `usage`, `finish_reason` (фрагмент потоку) |
| `Result` | `text`, `provider`, `model`, `usage`, `finish_reason`, `elapsed` |
| `ProviderError` | `kind`, `message`, `retryable`, `retry_after`, `detail` |
| `Provider` | `complete(request)` / `stream(request)` (Protocol) |

### Види збоїв (`ProviderError.kind`)

| Kind | Коли | `retryable` |
|---|---|---|
| `timeout` | Провайдер не відповів вчасно | ✅ |
| `rate_limit` | 429 з боку провайдера | ✅ |
| `unavailable` | 5xx, обрив з'єднання | ✅ |
| `auth` | 401, невірний ключ | ❌ |
| `bad_request` | 400, провайдер відхилив запит | ❌ |
| `cancelled` | Перервано на наше прохання | ❌ |
| `unknown` | Решта | ❌ |

## Три таймаути

| Змінна | Що обмежує | Значення |
|---|---|---|
| `LLM_TIMEOUT` | Одна спроба (SDK) | **20 с** |
| `LLM_IDLE_TIMEOUT` | Бездіяльність у streaming | **8 с** |
| `LLM_TOTAL_TIMEOUT` | Весь запит із усіма спробами й паузами | **45 с** |

**Обґрунтування:** `check_env.py` на `gemini-3.5-flash-lite` показує
перший фрагмент через **1.5–2 с**, уся відповідь — **5–8 с**. Тому
`LLM_TIMEOUT=20` (×3), `LLM_IDLE_TIMEOUT=8` (×4), `LLM_TOTAL_TIMEOUT=45`
(2 повні спроби + backoff + запас).

## Повтори

`app/gateway.py`:

- повторюються лише `retryable=True` (`timeout`, `rate_limit`,
  `unavailable`);
- `auth`, `bad_request`, `cancelled`, `unknown` — не повторюються;
- backoff: `LLM_BACKOFF_BASE * 2^(attempt-1) + jitter`, обмежено
  `LLM_BACKOFF_MAX`;
- `Retry-After` провайдера — максимум із нашим backoff;
- якщо пауза перевищує залишок `LLM_TOTAL_TIMEOUT` — припиняємо
  (`error: timeout`, `detail="budget"`);
- кількість спроб — `LLM_MAX_ATTEMPTS`.

## Запасний варіант

`LLM_FALLBACK`:
- `none` — вимкнено;
- `mock` — підставний провайдер;
- назва моделі — та сама адреса й ключ, інша модель.

Fallback вмикається **після всіх спроб** основного провайдера. У
результаті — `fallback: true`, сторінка показує позначку «запасний
варіант».

## Одночасність і частота

| Що | Де | Як |
|---|---|---|
| `LLM_MAX_CONCURRENT` | `gateway.py` | `threading.Semaphore` на весь застосунок |
| `RATE_LIMIT_PER_MINUTE` | `limits.py` | Ковзне вікно 60 с на клієнта |

**Різниця:** одночасність — «скільки звернань до провайдера виконується
зараз», частота — «скільки замовлень за хвилину дозволено одному
клієнту».

## Фонова генерація

`app/jobs.py`:

- `start(sample, client)` → `Draft` у статусі `queued`, запускає
  `threading.Thread`, повертає одразу;
- потік: `running` → `on_delta` (фрагменти) → `done` (або `failed` /
  `cancelled`);
- `subscribe(draft_id, since)` — генератор подій для SSE;
- `cancel(draft_id)` — ставить `threading.Event`.

### Події

| Event | Дані |
|---|---|
| `status` | `{status, attempt, provider, model, fallback, detail}` |
| `delta` | `{text}` |
| `done` | `{text, provider, model, usage, elapsed, attempts, fallback, warnings}` |
| `error` | `{kind, message, retryable}` |
| `cancelled` | `{}` |

**Гарантія:** жодна чернетка не лишається в `running` — `except`
ставить `failed` і `error`.

## Скасування

| Сценарій | Статус | Що бачить оператор |
|---|---|---|
| Під час генерації | `cancelled` | Текст, що встиг прийти |
| Вже завершена | 400 | «Чернетка вже done, скасувати не можна» |
| Невідома | 404 | «Чернетки X не знайдено» |

## Схема чернетки

`app/drafting.py`. Інструкція для моделі: роль оператора, українською,
2–5 речень, лише на підставі фактів, не вигадувати сум/дат/номерів,
не згадувати внутрішні примітки.

`check()` повертає попередження: порожня / коротка / довга;
заборонені підрядки (`internal_note`, `card_last4`, `customer_id`);
ключові номери з фактів не згадано.

## Налаштування `.env`

```env
# ---- Провайдер ----
LLM_PROVIDER=mock
LLM_FALLBACK=none

# ---- Модель ----
LLM_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai/
LLM_API_KEY=
LLM_MODEL=gemini-3.5-flash-lite
LLM_TEMPERATURE=0.3
LLM_MAX_TOKENS=600

# ---- Надійність ----
LLM_TIMEOUT=20
LLM_IDLE_TIMEOUT=8
LLM_TOTAL_TIMEOUT=45
LLM_MAX_ATTEMPTS=3
LLM_BACKOFF_BASE=0.5
LLM_BACKOFF_MAX=8
LLM_MAX_CONCURRENT=2

# ---- Обмеження власного API ----
RATE_LIMIT_PER_MINUTE=10

# ---- Підставний провайдер ----
MOCK_FIRST_DELAY_MS=600
MOCK_DELAY_MS=40
MOCK_FAILURE_RATE=0
MOCK_FAILURE_KIND=unavailable
```

Ключове: з `LLM_PROVIDER=mock` застосунок працює без ключа й
мережі. Перемикання на справжній провайдер — зміна одного рядка.

## Запуск

```powershell
cd "шлях-до\pr10"

python -m venv .venv
```

Відкрийте http://127.0.0.1:8000.

Для сценаріїв із перезавантаженням сторінки — запускайте без
`--reload`, інакше реєстр чернеток очиститься.

## Як користуватися сторінкою

Оберіть звернення (d01–d08).

«Скласти чернетку» — замовляє генерацію.

Текст приходить фрагментами у редаговане поле.

Шапка чернетки: статус, спроба, провайдер, час до першого
фрагмента.

«Скасувати» — зупиняє; текст, що встиг прийти, зберігається.

«Повторити» — нова чернетка (із підтвердженням, якщо редагували).

«Скопіювати» — у буфер.

«надіслати 5 поспіль» — 5 замовлень одночасно (429 на частину).

«Останні чернетки» — відкриття відтворює події (працює після
перезавантаження).

## Обробка помилок

| Збій | HTTP / стан |
|---|---|
| Невідоме звернення | 404 |
| Невідома чернетка | 404 |
| Скасування завершеної | 400 |
| Вичерпано частоту | 429 + `Retry-After` |
| Збій провайдера | `error` подія (не 500) |
| Несподівана помилка | 500 зі зрозумілим текстом |

Ключове:

збій провайдера не стає 500 — це `error` подія;

ключ, Traceback і текст винятку SDK на сторінку не потрапляють;

у журналі — `detail` з типом винятку.

## Безпека

API-ключ — лише в `.env`.

Ключ і повний текст запиту не потрапляють у помилки й журнал.

`internal_note`, `card_last4`, `customer_id` — не потрапляють у
чернетку; `drafting.check` перевіряє.

Обмеження частоти — від одного клієнта; одночасність — від
перевантаження провайдера.

## Відомі обмеження

`mid_stream`: текст накопичується між спробами й дублюється.
Правильно — очищати `draft.text` при новій спробі.

Fallback на `mock`: при неправильному ключі основного
провайдера `mock` падає з `unknown` замість того, щоб віддати текст.
У продакшені fallback зазвичай — інша реальна модель.

Позиція в черзі: при `LLM_MAX_CONCURRENT` оператор не бачить, що
його чернетка чекає в семафорі.

`attempts=0` у звіті: якщо помилка сталась на рівні шлюзу до
першого `on_status`, `draft.attempts` лишається 0. Це не «0 спроб»,
а «лічильник не оновився».

## Що виправляти далі

`jobs.runner.on_status` — очищати `draft.text` при `attempt > 1`.

`gateway._generate_with` — при fallback передавати причину в
`on_status`, щоб сторінка показала tooltip.

`gateway.generate` — показувати позицію в черзі при очікуванні
семафора.

`jobs.runner` — оновлювати `draft.attempts` до першого
`on_status`, щоб `attempts=0` не плутав у звіті.
