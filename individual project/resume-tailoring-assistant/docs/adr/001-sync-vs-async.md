# ADR-001: Синхронний vs фоновий режим

**Контекст:** основний сценарій — 1 резюме + 1 вакансія. Очікуваний час: 2–5 с (Gemini) + 0.5 с (локальні ембеддинги). Користувач чекає на результат у формі, без черги.

**Рішення:** синхронний `POST /api/analyze`.

**Наслідки:**
- (+) Простий контракт, прості тести, простіше показати на захисті.
- (+) Не потрібні черги, воркери, SSE.
- (−) Якщо Gemini відповідає повільно (>15 с), користувач чекає; таймаут — контрольована помилка 504.
- (−) Якщо в ПР16 додамо RAG із великим індексом, час може зрости; тоді перейдемо на фоновий режим — але контракт `POST /api/analyze` → 202 + `GET /api/requests/{id}` вже зарезервовано в ADR, тому зміна буде локальною.
