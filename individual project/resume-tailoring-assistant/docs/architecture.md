# Архітектура: Resume Tailoring Assistant

## Рівень 1 — Контекст

```text
┌─────────────┐       HTTP       ┌──────────────────────────┐      HTTPS      ┌────────────────┐
│ Користувач  │◀────────────────▶│ Resume Tailoring         │◀───────────────▶│ Google Gemini  │
│ (браузер)   │                  │ Assistant (система)     │                │ API            │
└─────────────┘                  └──────────────────────────┘                └────────────────┘
                                               │
                                               │ (локально, у процесі)
                                               ▼
                                  ┌──────────────────────────┐
                                  │ sentence-transformers    │
                                  │ all-MiniLM-L6-v2         │
                                  │ ChromaDB (in-memory)     │
                                  └──────────────────────────┘
```

**Межа модель / код / людина:**

- **Модель:** Gemini (поради, питання), `all-MiniLM-L6-v2` (ембеддинги).
- **Код:** парсинг PDF/DOCX, TF-IDF, маскування PII, пост-перевірка, сховище, HTTP.
- **Людина:** користувач вирішує, чи подавати резюме.

## Рівень 2 — Контейнери

```text
┌──────────────┐     HTTP/JSON     ┌──────────────────────┐      SQL      ┌────────────────┐
│ Streamlit /  │◀─────────────────▶│ FastAPI (server)     │◀─────────────▶│ SQLite         │
│ HTML+JS      │                  │ ключ, правила, виклик│              │ data/app.db    │
│ (інтерфейс)  │                  │ моделі               │              └────────────────┘
└──────────────┘                  └──────────┬───────────┘
                                             │
                                             │ контракт провайдера
                                             ▼
                                  ┌──────────────────────────┐
                                  │ Абстракція провайдера    │
                                  │ mock | openai_compat     │
                                  │ local                    │
                                  └──────────┬───────────────┘
                                             │
                                             ▼
                                  ┌──────────────────────────┐
                                  │ Gemini API / локальна   │
                                  │ модель (ПР15)           │
                                  └──────────────────────────┘

                                  ┌──────────────────────────┐
                                  │ RAG-індекс (ПР16)        │
                                  │ ChromaDB — пунктир       │
                                  └──────────────────────────┘
```

**Що існує зараз (ПР14):** інтерфейс, сервер, SQLite, mock-провайдер.

**Що з'явиться пізніше:** Gemini-провайдер (ПР15), RAG/ChromaDB (ПР16).

## Рівень 3 — Шари сервера (папки)

| Папка / модуль | Шар | Обов'язок |
|---|---|---|
| `app/main.py` | Контролер | Маршрути, перевірка входу, формат помилок, health, статика |
| `app/service.py` | Прикладний сервіс | Сценарій: прийняти резюме й вакансію, викликати оркестрацію, зберегти |
| `app/orchestration.py` | Оркестрація AI | Схема структурованого виходу, перевірка результату (заготовка ПР15) |
| `app/gateway.py` | Шлюз | Вибір провайдера за конфігурацією, таймаути, облік |
| `app/providers/base.py` | Абстракція провайдера | Контракт: запит → результат / помилка |
| `app/providers/mock.py` | Провайдер | Детермінований результат, структурований JSON, збої |
| `app/providers/openai_compat.py` | Провайдер | Заготовка ПР15 — контрольована помилка «не реалізовано» |
| `app/storage.py` | Сховище | `save_request`, `get_request`, `save_feedback` — модульний інтерфейс |
| `app/models.py` | Моделі даних | Pydantic-схеми всіх контрактів |
| `app/settings.py` | Конфігурація | Читання `.env` один раз, перевірка при старті |
| `app/telemetry.py` | Журнал | `request_id` у кожному записі, JSON-lines у `LOG_FILE` |
