# Фінальний проєкт з дисципліни «Розробка застосунків з ШІ»
# Зеркальний ATS-асистент (рекрутинг)
---

 **Суть:** Двосторонній асистент, який аналізує резюме з двох боків — для HR (пошук і ранжування кандидатів) та для кандидата (перевірка власного резюме на «прохідність» ATS-фільтрів, підгонка під вакансію, аналіз прогалин у навичках).

**Як працює:**
* **HR Mode:** завантажує вакансію + пачку резюме $\rightarrow$ отримує ранжований список з % відповідності, «червоними прапорцями» та згенерованими питаннями для інтерв'ю.
* **Candidate Mode:** завантажує своє резюме + текст вакансії $\rightarrow$ отримує ATS-оцінку, рекомендації щодо переформулювання досвіду та план підтягування навичок.

 **Стек:**

| Компонент | Інструмент |
| :--- | :--- |
| **UI** | Streamlit (дві вкладки: HR / Candidate) |
| **Парсинг PDF/DOCX** | `pdfplumber`, `python-docx` |
| **Базовий скоринг** | `scikit-learn` (TF-IDF + косинусна схожість) |
| **Семантичне порівняння** | `sentence-transformers` (`all-MiniLM-L6-v2`, локально на CPU) |
| **LLM для порад** | Google Gemini API (`Flash`, безкоштовний ліміт ~1500 запитів/день) |
| **Секрети** | `python-dotenv` (ключ у `.env`, додати в `.gitignore`) |

## Проблема та Цільова аудиторія

* **Проблема:** Процес скринінгу резюме є суб'єктивним і трудомістким для HR, а кандидати не розуміють, чому їхні резюме відхиляють ATS-системи.
* **Цільовий користувач:**
  1. **HR-менеджер** — прагне швидко знайти найкращих кандидатів та сформувати релевантні питання для інтерв'ю.
  2. **Кандидат** — прагне підвищити свої шанси на проходження автоматичного відбору та виявити прогалини в навичках.

---

## Основні Сценарії Використання

* **HR Mode:** Завантаження вакансії + пакету резюме $\rightarrow$ Отримання рейтингу відповідності + згенерованих питань для співбесіди.
* **Candidate Mode:** Завантаження власного резюме + цільової вакансії $\rightarrow$ Отримання звіту про «прогалини» та рекомендацій щодо переформулювання.

## Розмежування: AI-компоненти vs. Звичайний код

| Компонент | Тип | Роль | Чому саме так |
| :--- | :--- | :--- | :--- |
| **Парсинг PDF/DOCX** | Звичайний код | Витягування сирого тексту з файлів | `pdfplumber` / `python-docx` — детерміновані бібліотеки, не потребують AI. |
| **Препроцесинг тексту** | Звичайний код | Очищення, нормалізація, видалення стоп-слів | NLP-правила, регулярні вирази ($regex$). |
| **Базовий скоринг (TF-IDF)** | Звичайний код (ML) | Швидке обчислення косинусної схожості між текстом резюме та вакансії | `scikit-learn` — класичний ML, працює локально, без API. |
| **Семантичний пошук (Векторна БД)** | AI-компонент (додатковий) | Перетворення резюме та вакансій у вектори для пошуку «схожих за змістом», а не за ключовими словами | Використовує `sentence-transformers` для генерації ембеддингів та `ChromaDB` для зберігання й пошуку. |
| **RAG (Retrieval-Augmented Generation)** | AI-компонент (основний) | На основі знайдених релевантних фрагментів резюме генерує персоналізовані питання для HR або конкретні поради кандидату | Запит до Gemini API з контекстом, взятим з векторної БД. Це і є RAG. |
| **LLM-генерація** | AI-компонент | Створення фінальних текстових рекомендацій | Gemini API (`google-generativeai`, безкоштовний рівень). |

## Технічна Реалізація (Конкретні Кроки)

### 1. Векторна база даних та семантичний пошук (RAG-фундамент)
* **Векторне сховище:** Використання `ChromaDB` локально (в пам'яті або з логуванням на диск).
* **Генерація ембеддингів:** Модель `all-MiniLM-L6-v2` з бібліотеки `sentence-transformers`. Вона легка, працює на CPU і не потребує API-ключа.
* **Логіка:** Коли HR завантажує вакансію, створюється її ембеддинг. Далі для кожного резюме генерується ембеддинг і шукаються найближчі сусіди в `ChromaDB` (найбільш семантично схожі резюме).

### 2. Реалізація RAG (Обов'язковий додатковий компонент)
* **HR-сценарій (RAG):** Знайшовши ТОП-3 резюме, система бере найбільш релевантні фрагменти (наприклад, розділ «Досвід роботи») та надсилає їх у Gemini з промптом:
  > *"На основі цього досвіду кандидата та вимог вакансії, згенеруй 3 технічні питання для співбесіди, які перевірять його реальні навички."*
* **Candidate-сценарій (RAG):** Аналогічно, з промптом:
  > *"Порівняй досвід кандидата з вимогами вакансії. Знайди 2-3 навички, яких не вистачає, і запропонуй, як переформулювати існуючий досвід, щоб підкреслити релевантність."*

### 3. Безкоштовний LLM (Gemini API)
* Підключення через `google-generativeai`. Безкоштовний рівень Gemini API дозволяє виконувати запити без прив'язки банківської картки (з базовими лімітами RPM/RPD в консолі Google AI Studio).
