# ПР1. Інтеграція зовнішнього REST API

Веб-застосунок для відображення поточної погоди за назвою міста з інтеграцією публічного API **Open-Meteo**.

Проєкт реалізовано на **FastAPI** з використанням асинхронних HTTP-запитів. Застосунок підтримує обробку помилок, кешування запитів, двомовний інтерфейс (**UA / UK**) та сучасний **Glassmorphism UI** із динамічною зміною теми залежно від погодних умов.

---

## Основні можливості

* **Інтеграція з Open-Meteo API**

  * асинхронне геокодування міста;
  * отримання поточних погодних даних;
  * API-ключ не потрібен.

* **Багатомовність (i18n)**

  * українська мова (`UA`);
  * англійська мова (`UK`);
  * перемикання мови в реальному часі.

* **Адаптивний Glassmorphism UI**

  * сучасний інтерфейс;
  * напівпрозорі скляні картки;
  * ефект розмиття;
  * адаптація під різні розміри екрана.

* **Динамічні теми та ефекти**

  * `Day` — денна тема;
  * `Night` — нічна тема;
  * `Cloudy` — анімовані плаваючі хмари;
  * `Rainy` — генерація крапель дощу за допомогою JavaScript.

* **Надійність**

  * обробка таймаутів;
  * обробка відсутності мережі;
  * обробка помилок API;
  * перевірка існування міста;
  * обробка порожнього вводу;
  * обробка некоректного формату відповіді.

* **Оптимізація**

  * кешування координат міст за допомогою `@lru_cache`;
  * структурована передача параметрів через `httpx`.

```powershell

```

```powershell

```

Активуйте віртуальне середовище:


Якщо PowerShell блокує запуск скриптів, виконайте:


Після цього повторно активуйте середовище:

```powershell
.venv\Scripts\Activate.ps1
```

### macOS / Linux

Створіть віртуальне середовище:

```bash
python3 -m venv .venv
```

Активуйте його:

```bash
source .venv/bin/activate
```

# API Endpoints

## `GET /api/weather`

Ендпоінт використовується для отримання поточних погодних даних для вказаного міста.

### Параметри запиту

| Параметр | Тип      | Обов'язковий | Опис                                                   |
| -------- | -------- | ------------ | ------------------------------------------------------ |
| `city`   | `string` | Так          | Назва міста, наприклад `Київ`, `London`, `Tokyo`       |
| `lang`   | `string` | Ні           | Мова відповіді: `uk` або `en`. За замовчуванням — `uk` |

---

## Приклад запиту

```text
GET /api/weather?city=Київ&lang=uk
```

Англійською мовою:

```text
GET /api/weather?city=London&lang=en
```

---

## Приклад успішної відповіді

HTTP-статус:

```text
200 OK
```

JSON:

```json
{
  "city": "Київ",
  "country": "Україна",
  "temperature": 18.5,
  "temperature_unit": "°C",
  "windspeed": 12.3,
  "windspeed_unit": "km/h",
  "weathercode": 3,
  "theme_class": "cloudy",
  "icon": "☁️",
  "description": "Хмаро з проясненнями",
  "time": "2026-09-13T12:00"
}
```

# Обробка помилок

Застосунок обробляє основні помилки під час роботи з API.

| HTTP-статус | Назва           | Причина                                          |
| ----------- | --------------- | ------------------------------------------------ |
| `400`       | Bad Request     | Порожня назва міста або некоректні параметри     |
| `404`       | Not Found       | Місто не знайдено в базі геокодування            |
| `502`       | Bad Gateway     | Погодний сервіс недоступний або повернув помилку |
| `504`       | Gateway Timeout | Перевищено час очікування відповіді від сервісу  |

Застосунок не завершується аварійно у випадку помилки зовнішнього API, а повертає відповідний HTTP-статус і зрозуміле повідомлення для користувача.

# Open-Meteo API

Для отримання погодних даних використовується публічний API **Open-Meteo**, який не потребує API-ключа.

## Геокодування

Назва міста перетворюється на географічні координати за допомогою:

```text
https://geocoding-api.open-meteo.com/v1/search
```

Схема роботи:

```text
Назва міста
     ↓
Open-Meteo Geocoding API
     ↓
Широта та довгота
     ↓
Open-Meteo Forecast API
     ↓
Поточні погодні дані
     ↓
FastAPI
     ↓
Веб-інтерфейс
```

## Прогноз погоди

Для отримання погодних даних використовується:

```text
https://api.open-meteo.com/v1/forecast
```

# Надійність та обробка запитів

У проєкті реалізовано такі механізми:

* Параметри запиту передаються структуровано через `httpx`.
* URL не склеюється вручну.
* Кожен HTTP-запит має обмеження часу — `timeout = 5.0s`.
* Оброблено недоступність зовнішнього сервісу.
* Оброблено таймаути.
* Оброблено HTTP-коди `4xx` та `5xx`.
* Оброблено несподіваний формат відповіді API.
* Оброблено ситуацію, коли місто не знайдено.
* Перевіряється відсутність ключа `results` у відповіді геокодування.
* Робота з API винесена в окремий модуль `app/weather.py`.
* Веб-рівень `app/main.py` не містить деталей роботи HTTP-клієнта.
* Успішна відповідь проходить валідацію через Pydantic.
* При помилці повертається відповідний HTTP-статус.

# Динамічні теми

Тема інтерфейсу змінюється відповідно до отриманих погодних даних.

| Тема     | Умова         | Ефект                 |
| -------- | ------------- | --------------------- |
| `day`    | Денний час    | Денний фон            |
| `night`  | Нічний час    | Нічний фон            |
| `cloudy` | Хмарна погода | Плаваючі хмари        |
| `rainy`  | Дощова погода | Анімовані краплі дощу |

Для визначення дня та ночі використовується параметр:

```text
is_day
```

отриманий від Open-Meteo API.

# Кешування

Для оптимізації роботи застосунку використовується декоратор:

```python
@lru_cache
```

Кешуються координати вже знайдених міст.

Це дозволяє:

* зменшити кількість однакових запитів до геокодування;
* пришвидшити повторний пошук того самого міста;
* знизити навантаження на зовнішній API.

# Тестування

Робота застосунку перевірена на декількох сценаріях.

### Успішні запити

Перевірено отримання погоди для різних міст, наприклад:

```text
Київ
London
Tokyo
```

### Неіснуюче місто

Перевіряється ситуація, коли користувач вводить місто, якого немає в базі геокодування.

Очікуваний результат:

```text
404 Not Found
```

### Порожній ввід

Перевіряється введення без назви міста.

Очікуваний результат:

```text
400 Bad Request
```

### Помилки зовнішнього API

Перевіряється коректна обробка:

* недоступності мережі;
* таймауту;
* помилок сервера;
* некоректної відповіді API.

# Висновок

У результаті виконання практичної роботи було розроблено веб-застосунок для отримання та відображення поточних погодних даних за назвою міста.

Застосунок інтегрований із зовнішнім REST API **Open-Meteo**, використовує асинхронні запити через **httpx** та веб-фреймворк **FastAPI**. Реалізовано валідацію даних, обробку мережевих помилок і таймаутів, перевірку існування міста та кешування координат.

Також створено адаптивний **Glassmorphism-інтерфейс** із підтримкою української та англійської мов, динамічними погодними темами, анімаціями хмар і дощу. Роботу застосунку перевірено на різних містах, неіснуючому місті та порожньому введенні.
