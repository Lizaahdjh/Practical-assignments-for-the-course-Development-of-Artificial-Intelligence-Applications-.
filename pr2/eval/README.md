# Набір для оцінювання

Щоб судити про якість детектора, самих його передбачень мало: потрібні зображення, для яких ви **наперед знаєте правильну відповідь**. Цей набір ви складаєте самі — і він знадобиться не лише в ПР2, а й у наступних роботах курсу, де оцінювання стане систематичним.

## Що зробити

1. Покладіть **5–7 зображень** у папку `images/`.
2. Скопіюйте `expected.example.json` у `expected.json` і опишіть, які обʼєкти очікуєте на кожному зображенні.
3. Прогнавши детектор, порівняйте його результат із записаним очікуванням.

Зображення й `expected.json` до репозиторію не потрапляють — вони ваші (див. `.gitignore`).

## Які зображення обирати

Набір із семи однотипних фотографій нічого не покаже. Беріть різні випадки, зокрема незручні:

- кілька обʼєктів одного класу поруч — перевіряє дублі й пропуски;
- частково перекритий обʼєкт;
- дрібний обʼєкт удалині;
- погане освітлення або розмиття;
- зображення **без жодного** цільового обʼєкта — перевіряє хибні спрацювання;
- обʼєкт класу, якого модель не знає, — подивіться, чим вона його назве.

## Що фіксувати

Для кожного зображення порівняйте очікуване з отриманим і запишіть тип розбіжності:

| Тип помилки | Що сталося |
|---|---|
| **Пропуск** | обʼєкт є, детектор його не знайшов |
| **Хибне спрацювання** | детектор знайшов те, чого немає |
| **Неправильний клас** | обʼєкт знайдено, але названо не тим |
| **Дубль** | один обʼєкт зарахований кілька разів |

Окремо поспостерігайте, як на цю картину впливає **поріг упевненості**: підніміть його й подивіться, що зникає першим — хибні спрацювання чи справжні знахідки.

Назви класів беруться з набору COCO, на якому навчено модель (`person`, `car`, `bottle`, `chair`, …). Повний перелік — у документації Ultralytics.
