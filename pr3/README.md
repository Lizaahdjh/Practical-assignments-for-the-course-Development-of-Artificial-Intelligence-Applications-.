# ПР3. Інтеграція великої мовної моделі через API

Веб-застосунок **помічника служби підтримки інтернет-магазину**.

Користувач вводить звернення довільним текстом і отримує відповідь на підставі правил магазину. Разом із відповіддю відображаються **час виконання запиту** та **назва використаної моделі**.

Застосунок використовує зовнішню велику мовну модель через API та передає системну інструкцію, контекст магазину і звернення користувача окремими частинами запиту.

---

##  Мета роботи

Метою практичної роботи є створення веб-застосунку з інтеграцією великої мовної моделі через API.

Застосунок повинен:

* приймати текстове звернення користувача;
* передавати його до LLM через API;
* використовувати окремий контекст із правилами магазину;
* формувати відповідь на основі заданих правил;
* не вигадувати інформацію, якої немає в контексті;
* обробляти помилки API;
* вимірювати час виконання запиту;
* відображати назву використаної моделі;
* дозволяти змінювати модель і параметри через змінні середовища;
* порівнювати різні конфігурації моделі.

#  Налаштування

У проєкті використовується модель:

```text
gemini-3.5-flash-lite
```

Взаємодія з моделлю здійснюється через **OpenAI-сумісний інтерфейс Gemini**.

Основні параметри задаються у файлі `.env`.

## Змінні середовища

```env
LLM_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai/
LLM_API_KEY=<ваш ключ з Google AI Studio>
LLM_MODEL=gemini-3.5-flash-lite
LLM_TEMPERATURE=0.2
LLM_MAX_TOKENS=500
LLM_TIMEOUT=30
LLM_MAX_RETRIES=2
LLM_RETRY_DELAY=2.0
```

### Опис параметрів

| Змінна            | Опис                                    |
| ----------------- | --------------------------------------- |
| `LLM_BASE_URL`    | Адреса OpenAI-сумісного API             |
| `LLM_API_KEY`     | Ключ доступу до API                     |
| `LLM_MODEL`       | Назва мовної моделі                     |
| `LLM_TEMPERATURE` | Рівень випадковості відповіді           |
| `LLM_MAX_TOKENS`  | Максимальна кількість токенів відповіді |
| `LLM_TIMEOUT`     | Максимальний час очікування відповіді   |
| `LLM_MAX_RETRIES` | Максимальна кількість повторних спроб   |
| `LLM_RETRY_DELAY` | Затримка між повторними спробами        |

#  API

Основний JSON-ендпоінт застосунку:

```text
POST /api/ask
```

Він приймає звернення користувача та передає його до мовної моделі.

Схема роботи:

```text
POST /api/ask
       ↓
Перевірка запиту
       ↓
Завантаження context.md
       ↓
Формування повідомлень
       ↓
LLM API
       ↓
Обробка відповіді
       ↓
JSON-відповідь
```

#  Вимірювання часу виконання

Під час кожного запиту вимірюється час, необхідний для отримання відповіді від мовної моделі.

Час виконання відображається користувачу разом із відповіддю.

Приклад інформації:

```text
Response time: 1.84 s
Model: gemini-3.5-flash-lite
```

Це дозволяє оцінювати швидкість роботи різних конфігурацій моделі.

---

#  Обробка помилок

У застосунку реалізовано обробку основних помилок під час взаємодії з API.

| HTTP-статус | Помилка               | Опис                                          |
| ----------- | --------------------- | --------------------------------------------- |
| `401`       | Authentication Error  | Некоректний або відсутній API-ключ            |
| `429`       | Too Many Requests     | Перевищено ліміт запитів                      |
| `500`       | Internal Server Error | Внутрішня помилка застосунку                  |
| `502`       | Bad Gateway           | Помилка або недоступність зовнішнього сервісу |
| `503`       | Service Unavailable   | Сервіс тимчасово недоступний                  |
| `504`       | Gateway Timeout       | Перевищено час очікування відповіді           |

Також передбачено повторні спроби виконання запиту у випадках, коли це доцільно.

Кількість повторних спроб та затримка задаються параметрами:

```env
LLM_MAX_RETRIES=2
LLM_RETRY_DELAY=2.0
```

#  Тестовий набір

Для порівняння використано **6 звернень** різного типу:

1. Типове звернення.
2. Питання на межі правил магазину.
3. Питання поза межами заданого контексту.
4. Неоднозначне звернення.
5. Некоректний ввід.
6. Спроба переписати або змінити інструкцію.

Такий набір дозволяє перевірити не тільки якість звичайних відповідей, а й поведінку моделі у нестандартних ситуаціях.

#  Результати порівняння

Основний висновок порівняння:

> Для задач підтримки клієнтів доцільно використовувати низьке значення `temperature` у діапазоні **0.0–0.2**.

Низька температура забезпечує:

* більш передбачувані відповіді;
* стабільні результати на однакові запити;
* меншу варіативність формулювань;
* кращу відповідність заданому контексту;

#  Примітка щодо вибору моделі

У процесі тестування було виявлено особливість роботи деяких моделей серії 3.x через OpenAI-сумісний інтерфейс.

Моделі з увімкненим режимом **thinking** можуть використовувати значну частину доступного бюджету токенів на внутрішнє міркування, через що видима текстова відповідь може бути неповною або відсутньою.

Тому для цього проєкту було обрано:

```text
gemini-3.5-flash-lite
```

Ця модель у використаній конфігурації забезпечує отримання видимого текстового результату та підходить для реалізації помічника служби підтримки.

# Висновок

У результаті виконання практичної роботи було розроблено веб-застосунок **помічника служби підтримки інтернет-магазину** з інтеграцією великої мовної моделі через API.

Застосунок реалізовано на **FastAPI**, а логіку взаємодії з мовною моделлю винесено в окремий модуль `app/llm.py`. Правила магазину зберігаються у файлі `context.md`, завдяки чому поведінку помічника можна змінювати без редагування програмного коду.

Конфігурація моделі, API-ключ та параметри запитів задаються через змінні середовища. Реалізовано обробку таймаутів, перевищення лімітів, недоступності сервісу та помилок автентифікації.

Також проведено порівняння двох конфігурацій із різними значеннями `temperature`. За результатами тестування для задач служби підтримки доцільним є використання низької температури **0.0–0.2**, оскільки це забезпечує більш передбачувані та стабільні відповіді.
